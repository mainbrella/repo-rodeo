## Implementation

- The CLI, adapter factory and recovery command now recognize Daytona and its
  `DAYTONA_API_KEY`. The official API endpoint is `https://app.daytona.io/api`.
- The default mode is `saved-workspace`, using the default container snapshot
  (`--size default`). One filesystem snapshot supplies three planned restores.
  [Container snapshots require a stopped source](https://www.daytona.io/docs/en/snapshots/#create-snapshot-from-sandbox).
  Capture stops the source, snapshots it, then restarts the container. The runner
  expects no inherited HTTP listener and explicitly launches fresh servers.
- [Container native forks are unsupported](https://www.daytona.io/docs/en/sandboxes/#fork-sandboxes).
  VM memory forks, volumes and warm pools remain separate unimplemented modes.
  They are not substituted for container snapshot restores.
- The guest installs checksum-verified Node `22.22.2` and pins PATH at invocation.
  The default toolbox did not actually run commands as root despite reporting
  `user: root`. Passwordless `sudo -n` supplies the required `/opt` and `/workspace`
  permissions. Binary uploads stream to `/tmp` and are then installed into place.
- Private previews use `x-daytona-preview-token`, restricted to their own origin
  in host requests and Chromium interception, including same-origin redirects.
  Standard Daytona preview tokens are sandbox-wide credentials and remain private.
  Stopping the source rotates its token; the adapter discards its cached client.
- Managed jobs use durable session and command IDs. A fresh client can retrieve
  retained stdout and read remaining bytes from a recorded offset. This polling
  recovery does not exercise live stream disconnection or dashboard reconnection.
  Guest `timeout` bounds asynchronous command runtime.
- Logical SDK mutations and ownership are journaled durably. Unknown admissions
  are never replayed. `--check-idempotency` reports unsupported. A cached completed
  local journal is not evidence of provider keyed replay.
- Recovery binds the exact original key fingerprint, discovers run-owned resources
  by exact persisted names, and polls inventory for deletion propagation. Rotated
  key recovery is not implemented. Current-key metadata does expose organization
  identity; using that for account-bound rotated-key recovery is future work.
- Each sandbox requests a 30-minute wall-clock TTL. Immediate auto-delete is
  disabled so stopping the source does not destroy it before snapshot capture.
  The final code allows ten minutes for capture; that change has not been rerun
  in the cloud. Persistent snapshots do not inherit the source's TTL.
