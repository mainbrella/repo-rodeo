## Implementation

- Native `memory-fork` calls E2B's fork API once with `count: 3`, so all three
  controls originate from one capture. Source and branch lifetimes are explicitly
  30 minutes, with kill on timeout.
- The runner checks inherited listener, process nonce, and PID before stopping
  each copied server and launching a new one for patch verification. It checks
  every branch's expected hashes and independent marker after all controls finish.
- Public traffic is disabled. Preview requests use a private traffic token,
  scoped to the preview origin. Same-origin redirects are bounded; credentials
  are not forwarded to another origin.
- The guest installs Node `22.22.2` from the official Linux distribution and
  verifies its SHA-256 against the published manifest. Command invocation sets
  PATH explicitly because the template's login shell otherwise selects old Node.
- Managed command reconnection uses the SDK command PID and durable guest stdout.
  Its cursor is a byte offset in that log, not MainBrella-style server SSE replay.
- E2B has no documented keyed replay contract for create/fork/snapshot requests.
  SDK mutation retries are disabled; ambiguous provisioning is not reissued and
  prevents fully confirmed cleanup. Run metadata identifies resources to remove.
- Cleanup pins the exact authenticated key fingerprint. The API-key interface
  does not expose a stable team identity, so rotated-key recovery is not supported.
  Monthly workspace reservation counters and account capacity limits are unavailable
  through this adapter and are reported as unavailable, rather than zero.

## Reproduction

Set `E2B_API_KEY` in the host environment, then run:

```sh
npm run experiment -- --provider e2b --mode memory-fork \
  --source ../web --source-ref 3eb5f1d144324793492bed765d94bc6463614ef3 \
  --seed 12345 --check-idempotency
```

The idempotency check is explicitly unsupported for E2B; the option does not
inject response loss or replay an uncertain mutation. `saved-workspace` is a
separate persistent filesystem-only snapshot implementation and remains live
unqualified here. It requires project enablement and fails explicitly if disabled.
Pause/resume, volumes, warm pools, AI repair agents, physical snapshot reclamation,
and actual charges remain unmeasured.

Only sanitized version-2 results and allowlisted document observations are suitable
for sharing. Raw request journals, reports, traces, screenshots, and traffic tokens
remain private after sandbox deletion.
